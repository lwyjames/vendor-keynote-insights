# Video access and evidence capture

## Diagnose before concluding failure

Use only the designated source and currently permitted tools. Respect connector-first rules, browser authorization and security rejections; this workflow grants no access or bypass permission. Report a failure at its observed stage, not as a blanket inability to watch the service.

1. Open the exact designated Bilibili page. Distinguish a page-loading failure from an absent player.
2. Confirm actual playback using advancing player time and changing pictures. A loaded page, poster or transcript is not proof of playback.
3. Inspect the available quality and actual loaded stream resolution through supported controls. Distinguish playable lower-quality video from a login restriction on higher quality.
4. When login is required, follow the tool's authentication guidance and supported user handoff. Never ask for passwords in chat. After user completion, reuse the same authorized session and recheck playback/quality without another redundant permission request.
5. Locate one unambiguous scene, pause and save a sample frame. Verify player time, visible subject, saved file existence and actual pixel dimensions before batch capture. Wait for a download to finish before navigating away.
6. Retry only when an observed cause changes (login completed, player loaded, corrected transcript, permitted quality selection). Avoid blind repeated attempts. On security denial, do not route around it; state the blocked stage and continue independent authorized work.

Do not assume Bilibili success implies YouTube capture capability. Assess each site's available permitted route separately. Never substitute another video without the user's designation.

## Preflight transcript timecodes

Check parseability, repeated timestamps, monotonic order and range against player duration. Retain untimed text for content analysis when timing fails; do not fabricate locators. Sample matching content near the beginning, middle and end. Apply a constant offset only if anchors support it; otherwise use segment-specific anchors and confirm each target in the player. Do not hard-code an offset from another project.

For every capture retain transcript locator, actual player timestamp, visible evidence, target stable slide IDs and uncertainty. Use player time as the frame index's authoritative video locator.

## Select and verify assets

Evaluate designated official pages early alongside video. Prefer suitable high-resolution official imagery for product appearance, materials and structure. Prefer observed video for gestures, posture changes and demonstrated workflows. Official images do not prove a live demonstration or availability. A single still cannot prove seamless continuity: use paired/sequence frames or qualify the claim.

Inspect supported higher-resolution image variants without inventing URLs. Record stream pixel dimensions and screenshot pixel dimensions separately; browser scaling does not create source detail. Preserve originals. Track `planned`, `saved`, and `final-crop-reviewed` separately. Check the crop in the finished slide, preserving the evidence subject. Keep provenance in notes/registers, not visible source labels. If mandatory attribution conflicts with the desired presentation, choose another permitted asset.
